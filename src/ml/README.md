# PortFlow AI — ML Module

> ⚠️ **Synthetic data only.** All training data is generated by `src/data/generator.py` with `seed=2026`. No real port or vessel data is used. Metrics are illustrative and make no real-world accuracy claims.

## Purpose

This module trains a scikit-learn **congestion risk classifier** for six-hour port operation windows. The classifier predicts risk labels (`LOW`, `MEDIUM`, `HIGH`) based on pre-window schedule data.

The `baseline_rule_v1` heuristic (in `src/backend/app/services/congestion.py`) remains the production fallback and is not replaced by this classifier.

## Feature Columns (no leakage)

Only columns available **before** the prediction window are used:

| Feature | Type | Description |
|---|---|---|
| `arrivals_in_window` | numeric | Vessel count scheduled in the 6-hour bucket |
| `raw_occupancy` | numeric | `arrivals / berth_count` |
| `avg_expected_containers` | numeric | Mean container moves per arriving vessel |
| `crane_to_berth_ratio` | numeric | Operational cranes ÷ operational berths |
| `priority_min` | numeric | Minimum priority integer (1 = highest urgency) |
| `hour_of_day` | numeric | UTC hour of bucket start |
| `day_of_week` | numeric | Weekday of bucket start (0=Mon) |
| `scenario` | categorical | Synthetic scenario name |

### Forbidden columns (leakage guard)

These columns represent **future outcome data** and are explicitly rejected:

`waiting_minutes`, `service_minutes`, `actual_arrival`, `berth_start`, `berth_end`, `actual_departure`, `average_moves_per_hour`, `cranes_used`, `assigned_berth_id`, `delay_reason`

From `docs/DATA_DICTIONARY.md`:

| Label | Occupancy threshold |
|---|---|
| `HIGH` | ≥ 0.7 |
| `MEDIUM` | 0.5 – 0.699 |
| `LOW` | < 0.5 |

## Pipeline Architecture

```
SimpleImputer(mean)   ← numeric features
OneHotEncoder         ← scenario (categorical)
       ↓
RandomForestClassifier(n_estimators=100, random_state=2026, class_weight="balanced")
```

## Limitations

1. **Synthetic data only** — trained on ~40–60 rows; metrics are illustrative.
2. **No real-world accuracy** — not validated on live port operations.
3. **Small dataset** — chronological split has very small test sets; macro F1 varies by run only if the generator changes.
4. **No hyperparameter search** — single configuration for reproducibility.
5. **`baseline_rule_v1`** remains the API production fallback until the ML pipeline is integrated into the API (Plan 6).
